เจตนา

ทำให้หน้า agent-team logs ใช้งานได้เมื่อ log ยาว (กรอง/เรียง/แบ่งหน้า 10/20/50), แยก agent แต่ละ role ด้วยสี/ไอคอน และจัด typography ให้อ่านภาษาไทยสบายตา

มีวิธีที่ง่ายกว่าไหม: มีบางส่วน:

  • ส่วนการเรียก agent: โปรเจกต์จริง (mail-sender) มี 11 call ต่อรอบ ตัวกรองกับการเรียงอย่างเดียวก็แก้ปัญหาได้เกือบหมด ส่วน pagination ของ call คุ้มเฉพาะงาน BUILD ใหญ่ที่มี QA หลายรอบ
  • Timeline ได้ประโยชน์จาก pagination ชัดกว่า

ผู้ใช้ขอ pagination ทั้งสองส่วนเอง plan จึงไม่ผิดตรงนี้ แค่บันทึกไว้ให้รู้ว่าเป็นส่วนที่ตัดได้ถ้าอยากให้งานเล็กลง

ไล่แล้วยืนยันว่าเข้ากับโค้ดจริง

  • render.test.ts เดิม: ตรวจ data.defaultRun, next.defaultRun, document.hidden, (ไม่ได้เรียก agent) และจำนวน </script> ซึ่ง plan แก้จาก 3 เป็น 4 ครบทั้งสองที่ และ PAGE_JS ใหม่ยังมีข้อความที่เทสต์เดิมต้องการครบ
  • รัน JS จาก plan ได้: ดึง LIST_JS/PAGE_JS ออกจาก brief มา new Function แล้ว parse ผ่าน ไม่มี ${ และไม่มี </script
  • ค่าที่เทสต์คาดไว้ถูกต้อง: ไล่ค่าที่คาดใน list-assets.test.ts ด้วยมือ ครบทั้งลำดับ duration/cost/turns แบบค่าว่างอยู่ท้าย, pageOfCall (23→หน้า 3 / desc→หน้า 1 / ถูกกรอง→0) และการค้นหา BOOM/AGENT.RESULT
  • DOM test: ค่าที่คาดไว้สอดคล้องกับข้อมูล fixture (qa 13 / backend 12, ปุ่มกระโดด #24 ⚙️ backend, หน้า 2/2) และหลังแก้ใน plan แล้ว เทสต์ป้าย role ค้นเฉพาะภายใน <details> จึงไม่ผ่านเพราะไปเจอป้ายในการ์ด
  • ลำดับ script: LIST_JS ประกาศ var AgentTeamList ใน classic script จึงเป็น property ของ window และ PAGE_JS ที่โหลดทีหลังเรียกใช้ผ่าน window.AgentTeamList ได้

Findings

MAJORTask 2 ยังโหลดฟอนต์จาก Google Fonts ซึ่งขัดกับทิศทางล่าสุด (ฝังฟอนต์) และกติกา offline/ไม่เรียกภายนอกเดิม

ทำไมสำคัญ
  • request ออกไปทุกครั้ง: logs.html เป็นไฟล์ที่เปิดจาก file:// และส่งต่อให้คนอื่นได้ ทุกครั้งที่เปิดจะส่ง request ไป fonts.googleapis.com/gstatic ซึ่งบอกได้ว่ามีคนเปิดดู log ของโปรเจกต์นี้เมื่อไร
  • หน้าตาไม่ตรงกัน: เครื่องที่ offline หรือถูกบล็อกจะได้ฟอนต์คนละแบบ ซึ่งขัดกับเป้าหมาย "เหมือนกันทุกเครื่อง" ของ typography
  • ต้องแก้หลายที่: README (Task 3 Step 5) และเทสต์ใน Task 2 ผูกกับลิงก์ Google ไว้ทั้งหมด
หลักฐาน
Task 2 Step 3 เพิ่ม <link rel="stylesheet" href=FONT_STYLESHEET> + preconnect, เทสต์ Step 1 ตรวจ fonts.googleapis.com, README bullet ที่ 3 ใน Task 3 บอกว่า "มี request ไป fonts.googleapis.com"
แนวทางแก้ไข
เขียน Task 2 ใหม่ให้ฝังฟอนต์:
  • เก็บ woff2 แบบ variable 3 ไฟล์ที่ assets/fonts/: Noto Sans Thai (thai ~31KB), Inter (latin ~48KB), JetBrains Mono (latin ~31KB) พร้อม OFL.txt
  • เพิ่ม "assets" ใน "files" ของ package.json (ตอนนี้มีแค่ bin/src/skills/scripts/tsconfig.json — ถ้าลืม เครื่องที่ติดตั้งจาก GitHub จะไม่มีฟอนต์โดยไม่มี error อะไรบอก)
  • render.ts อ่านไฟล์จาก TEAM_ROOT/assets/fonts แล้วสร้าง @font-face แบบ base64 พร้อม unicode-range อ่านครั้งเดียวแล้ว cache ถ้าหาไฟล์ไม่เจอให้ข้ามไป
  • เทสต์: ตรวจว่ามี @font-face 3 ชุดและไม่มี http ใน HTML
  • README: บอกว่าฟอนต์ฝังในไฟล์และ offline ได้

NITช่องค้นหา timeline re-render ทั้งหน้าทุกตัวอักษรที่พิมพ์

ทำไมสำคัญ
search.oninput → render() สร้าง DOM ใหม่ทั้งหน้า (การ์ด, timeline) และแทนที่ input เดิม กรณีทั่วไป plan กู้ focus และตำแหน่งเคอร์เซอร์ได้แล้ว แต่ IME ที่มี composition จะถูกตัดกลางคำเมื่อ element ถูกแทนที่ (แป้นไทย Kedmanee ไม่ได้ใช้ composition จึงไม่กระทบคนส่วนใหญ่) และหน้าที่เลือก 50 รายการต่อหน้าจะหน่วงทุกครั้งที่กดแป้น
หลักฐาน

ข้ามการ render ระหว่าง compositionstart–compositionend และหน่วง render ด้วย setTimeout ประมาณ 150ms หลังพิมพ์ตัวสุดท้าย
