Scrutinize — feature: PM free chat (พิมพ์คำถามแทนการเลือกตัวเลือกได้ทุกจุดตัดสินใจ)

repo agent-team · commit range 9138733..fc70302 (merged เข้า main แล้ว) · ตรวจวันที่ 2026-09-25 · ฐาน: โค้ดจริงบน working tree

1. เจตนา

สรุปด้วยคำพูดตัวเอง: ทำให้ตอนที่ระบบหยุดรอให้คนกดเลือก (ยืนยัน / ขอแก้ / ทำต่อ / รับงาน) คนสามารถพิมพ์คำถามคุยกับ PM ในบทสนทนาเดิมก่อน แล้วค่อยกลับมาเลือก โดยไม่เสียสถานะและไม่ต้องเริ่ม session ใหม่

มีวิธีที่ง่ายกว่าไหม — มี. ปัญหาจริงคือ “แยกไม่ออกว่าข้อความที่พิมพ์เป็นการตัดสินใจหรือคำถาม” ดีไซน์นี้เลือกเดาเอาจากข้อความ (parseChoice ไม่ตรง = ถือเป็นคำถาม) แล้วผลักภาระการแยกแยะที่เหลือ ไปไว้ใน prompt ของ PM (PM_PROMPT rule 4, src/prompts.ts:24) ซึ่งไม่มีการบังคับที่ระดับโค้ดเลย — finding B-1 ด้านล่างเกิดจากตรงนี้โดยตรง ทางที่เล็กกว่าและ deterministic กว่าคือทำ “คำถาม” ให้เป็น intent ที่ชัดเจน เช่น เพิ่มตัวเลือก ask เข้าไปในเมนู หรือให้ใช้ prefix ? นำหน้าเมื่ออยากถาม ได้ผล ~90% ของ feature นี้ โดยตัดทิ้งไปทั้งก้อน: ความกำกวมของ parseChoice, rule 4 ใน PM prompt, และเคสพิมพ์ผิดแล้วเสียเงินยิงหา PM

M-1 — PM ไม่เคยได้รับ “ตัวเลือกที่ค้างอยู่” ทำให้ rule 4 ของ PM_PROMPT ทำตามไม่ได้ใน 3 จาก 4 จุด (src/io-util.ts:20,25 เทียบกับ src/prompts.ts:24)

ทำไมถึงสำคัญ rule 4 สั่งว่า “ถ้าข้อความของ user คือหนึ่งในตัวเลือกที่ค้างอยู่ในรูปประโยคอื่น ให้บอกคำที่ต้องพิมพ์ให้ชัด” แต่โค้ดส่งเข้าไปแค่ result.text เปล่า ๆ — ไม่ส่งทั้ง prompt และ options PM จึงไม่รู้ว่าตอนนี้ตัวเลือกคือ confirm/revise หรือ accept/change ต้องเดาเอา ผลคือคำแนะนำที่ PM ให้จะชี้ตัวเลือกผิดคำ user ก็พิมพ์ผิด แล้ววนเสียเงินอีกรอบ

  • จุดเดียวที่ PM บังเอิญรู้ตัวเลือกคือ BUILD escalate เพราะมีข้อความ 'อธิบายตัวเลือก: continue / accept / abort' เขียนไว้ใน prompt ตั้งต้น (src/phases/build.ts:209) ส่วน REQUIREMENTS (requirements.ts:26), REVIEW (design.ts:58) และ DELIVER (deliver.ts:29) ไม่เคยส่งคำว่า confirm/revise/accept/change เข้า session เลย

3. สิ่งที่ไล่แล้วพบว่าถูกต้อง (เพื่อให้เห็นขอบเขตการตรวจ)

  • EOF / Ctrl+C ไม่ถูกกลืน — io.chooseOrText อยู่นอก try ของ decide() (io-util.ts:20 vs :24) error จาก CliIO.ask (cli.ts:65-66) จึงทะลุขึ้นไปถึง index.ts:63 ได้ถูกต้อง
  • Enter เปล่าไม่เสียเงิน และไม่วนฟรี — io-util.ts:22 continue ก่อนเรียก PM; loop ไม่มีทางหมุนเองเพราะทุกรอบต้องรอ ask ที่ block จริง (หรือ throw เมื่อ stdin ปิด)
  • persist ก่อนถาม — state.pmSessionId ถูก save ก่อนที่ user จะเห็นเมนูทุกจุด (requirements.ts:20-21, design.ts:53-54, build.ts:211-212, deliver.ts:25-26) และมีเทสยืนยันใน build/design/deliver
