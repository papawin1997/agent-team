Findings

MAJORค่า planning.model ที่ผู้ใช้ตั้งเองจะไม่มีผลในระดับ standard และไม่มีการแจ้งเตือน

ทำไมสำคัญ
ผู้ใช้ที่มี config เดิม หรือ copy ตัวอย่างจาก README (README.md:206 "planning": { "model": "claude-opus-5" }) จะได้ Sonnet ในงาน standard ทั้งที่ตั้งใจให้ใช้ Opus ทุกงาน ส่วน README บรรทัด 211 เขียนว่า "ระดับที่ไม่ได้ใส่ใช้ model ปกติ" ซึ่งทำให้เข้าใจผิดยิ่งขึ้น
หลักฐาน
mergeConfig (src/config.ts:132-141) เก็บ modelByLevel ของ default ไว้เมื่อ patch มีแค่ model จากนั้น resolveModel (src/config.ts:22) ใช้ modelByLevel.standard ก่อน model ผลคือ mergeConfig(DEFAULT, {roles:{planning:{model:'X'}}}) ได้ standard = claude-sonnet-5 ส่วน full = X (final reviewer รันยืนยันแล้ว)
แนวทางแก้
ใน mergeConfig ถ้า patch ตั้ง model แต่ไม่ได้ตั้ง modelByLevel ให้ลบ modelByLevel ที่ได้มาจาก default ทิ้ง เพื่อให้ model ที่ผู้ใช้เลือกมีผลทุกระดับ พร้อมเพิ่มเทสต์ 1 ตัว และเพิ่มประโยคใน README ว่า "ตั้ง model อย่างเดียว = ใช้ทุกระดับ"

MAJORQA และ worker ได้ requirements ของทั้งโปรเจกต์แต่เห็นแค่ task เดียว จึงอาจตัดสินหรือทำงานเกินขอบเขตของ task

ทำไมสำคัญ
QA อาจให้ FAIL เพราะ "ยังไม่มีฟีเจอร์ Y" ทั้งที่ Y เป็นงานของ task อื่น ทำให้ worker ต้องสร้างงานนอก task และเสียรอบแก้ ค่าใช้จ่ายที่เพิ่มจากรอบแก้แบบนี้อาจมากกว่าที่ประหยัดจากการตัด context เพราะ QA ที่ FAIL 1 รอบต้องเรียก worker และ QA ใหม่อีกอย่างละครั้ง
หลักฐาน
QA_PROMPT (src/prompts.ts) สั่งให้ "Compare them with the task's acceptance criteria, the design ... and the requirements" ส่วน buildQaPrompt ยังส่ง Requirements ครบทุกฟีเจอร์ แต่ design ที่ส่งไม่มีรายการ task แล้ว ตัวอย่างเช่นใน mail-sender ที่มี 13 task QA ของ task แรกจะเห็น requirements ของทั้ง 13 task โดยไม่รู้ว่าส่วนไหนเป็นของ task อื่น สิ่งเดียวที่ช่วยได้ตอนนี้คือหัวข้อ "other tasks are omitted" ใน prompt ซึ่งไม่ได้สั่งว่าห้ามตัดสินส่วนที่เป็นของ task อื่น ความเสี่ยงนี้เทสต์ unit วัดไม่ได้
แนวทางแก้
เพิ่มประโยคเดียวใน scopedDesignSection (หรือใน system prompt ของ QA, worker และ Security): "The requirements describe the whole project; other tasks (omitted) implement the parts outside this task. Implement/judge only this task's acceptance criteria and never report features owned by other tasks as missing."

NITถ้ายกระดับจาก standard เป็น full ตอน REVIEW งาน full จะใช้ design ที่ Sonnet ออกแบบไว้

ทำไมสำคัญ
พฤติกรรมเปลี่ยนไปจากเดิมโดยไม่มีใครบอก ก่อน E ทุก design ออกแบบโดย Opus แต่ตอนนี้งาน full ที่มาจากการยกระดับ (ซึ่งเกิดเพราะเจอคำเสี่ยง) ใช้ design ที่ Sonnet ออกแบบ โดยมี Security ตรวจ design ในระดับ full เพิ่มให้
หลักฐาน
runReview (src/phases/design.ts:92-100) เปลี่ยนเป็น state.level='full' แล้วใช้ design เดิมต่อ โดยไม่ออกแบบใหม่
แนวทางแก้
ยอมรับพฤติกรรมนี้ได้ แค่เขียนไว้ใน README ถ้าอยากให้งานเสี่ยงได้ design จาก Opus เสมอ ให้เพิ่มตัวเลือก "full + ออกแบบใหม่" แต่ต้องแลกกับค่า Planning อีก 1 ครั้ง

NITเทสต์ของ state เก่าที่ไม่มี level จะผ่านได้แม้ runner ไม่ถูกเรียกเลย

ทำไมสำคัญ
ถ้า runner ไม่ถูกเรียกเลย loop ที่ assert toBeUndefined() จะไม่มีรอบให้ทำงาน เทสต์จึงผ่านทั้งที่โค้ดพัง
หลักฐาน
เทสต์ "state เก่าไม่มี level" ใน tests/phases/build.test.ts ไม่ได้ตรวจว่ามีการเรียกกี่ครั้งหรือ role อะไรบ้าง ซึ่งตรงกับ minor T3-m2 ใน ledger
แนวทางแก้
เพิ่มบรรทัด expect(roles(runner.calls)).toEqual(['backend', 'qa', 'security']) ในเทสต์นั้น

จุดที่ไล่โค้ดแล้วไม่พบปัญหา

  • level เก่าค้างใน BUILD เป็นไปไม่ได้: ctx.level ถูก copy ครั้งเดียวตอนเริ่ม runBuild ส่วน escalateLevel เปลี่ยนเฟสเป็น DESIGN แล้ว buildTask return 'escalated' ทันที จึงไม่มีการใช้ ctx เดิมต่อ
  • ทุกจุดที่เปลี่ยน level (level.ts:127, 234, 243, 266) ตั้งค่าก่อนเรียก runner ครั้งถัดไปเสมอ
  • worker resume ไม่ข้ามระดับ: restoreBaseDesign ลบ workerSessionId ทิ้ง
  • ทุกเส้นทาง retry ส่ง level ต่อครบ: ทั้ง re-ask และ recovery ใช้ level เดิม
  • PM ไม่ได้รับ level และ schema ปฏิเสธ pm.modelByLevel
  • log viewer (parse-log.ts:114-131) ได้รับ model ที่ resolve แล้วซึ่งถูกต้องกว่าเดิม และข้าม field level ไป
  • Planning และ Security ตอนตรวจ design ยังเห็นทุก task และมีเทสต์ยืนยัน

Verdict

fix-then-ship

เหตุผลหลัก: การตั้ง planning.model ใน config จะไม่มีผลในระดับ standard โดยไม่มีการแจ้งเตือน และ README ก็พาให้เข้าใจผิด ทั้งสองข้อ major แก้ได้ด้วยโค้ดไม่กี่บรรทัดพร้อมเทสต์
