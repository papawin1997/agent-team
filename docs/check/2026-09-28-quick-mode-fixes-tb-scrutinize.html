Findings

NITSQL ยังไม่จับ query คอลัมน์เดียว, aggregate และชื่อที่อยู่ในเครื่องหมายคำพูด (src/risk.ts:65)

ทำไมถึงสำคัญ
คำขอแบบ "นับ order ด้วย SELECT COUNT(*) FROM orders" หรือ "select name from users where id = 1" จะไม่ขึ้นคำเตือน SQL แต่ผลกระทบต่ำ เพราะคำเตือนนี้เป็นแบบ best-effort ตามที่ README บอกไว้ และถ้าข้อความมีคำว่า sql ก็ยังถูกจับอยู่ดี
หลักฐาน
ผลจาก probe: SELECT COUNT(*) FROM orders → [] · select name from users where id = 1 → [] · UPDATE "users" SET name = 1 → [] (ส่วน SELECT u.id, u.name FROM users u → sql ✓)
แนวทางแก้ไข
เพิ่ม alternation ที่เป็นสัญญาณ SQL ชัด ๆ: \bselect\s+(count|sum|avg|min|max)\s*\(, \bselect\s+[\w.]+\s+from\s+[\w."`]+\s+(where|join|order\s+by|group\s+by|limit)\b และให้ identifier รับ "` ได้ ต้องยืนยันด้วยว่า "select a color from the palette" ยังไม่ถูกจับ

NITหมวด delete ภาษาไทยยังจับแบบ "มีคำครบ ที่ไหนก็ได้" ไม่ได้ดูว่าคำอยู่ใกล้กัน (src/risk.ts:46-50)

ทำไมถึงสำคัญ
"เพิ่มปุ่มลบในหน้าผู้ใช้ ให้แสดงทุกหน้า" ถูกเตือนว่าเป็น delete แม้ไม่ได้ลบข้อมูลจำนวนมาก ข้อนี้ผิดไปทางระวังเกิน ซึ่งปลอดภัยกว่าพลาดเคสเสี่ยง ผลที่เกิดคือผู้ใช้เห็นคำเตือน ⚠ เกินมาหนึ่งครั้ง
หลักฐาน
probe: เพิ่มปุ่มลบในหน้าผู้ใช้ ให้แสดงทุกหน้า → ["delete"]
แนวทางแก้ไข
(ไม่บังคับ) ให้ "ทั้งหมด"/"ทุก" ต้องตามหลัง "ลบ" ภายในประมาณ 20 ตัวอักษร เช่น /ลบ[^\n]{0,20}?(ทั้งหมด|ทุก)/ แล้ว AND กับคำนามข้อมูลเหมือนเดิม วิธีนี้ทั้ง 6 เคสเดิมยังผ่าน

คำตัดสิน

ship  ข้อ major (SQL หลาย column) และ nit ทั้ง 4 ข้อจากรอบก่อนถูกปิดแล้วและตรวจยืนยันแล้ว ที่เหลือเป็น nit ระดับ heuristic ของคำเตือน ไม่ได้บล็อกการ merge
