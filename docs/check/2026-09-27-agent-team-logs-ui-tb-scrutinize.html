Scrutinize: หน้า agent-team logs — sort/filter/pagination, สี role, ฟอนต์ฝัง

2026-09-27 · branch feat/agent-team-logs-ui · f5c4d32..c5f35e4 · plan: docs/plan/2026-09-27-agent-team-logs-ui.html

เจตนา

ทำให้หน้า log ใช้งานได้เมื่อรายการยาว (กรอง/เรียง/แบ่งหน้า 10/20/50), แยก agent แต่ละ role ด้วยสีและไอคอน และอ่านภาษาไทยสบายตาด้วยฟอนต์ที่ฝังไว้ในไฟล์ (ใช้ได้ offline)

มีวิธีที่ง่ายกว่าไหม: มี ในเชิงโครงสร้าง (ดู finding ข้อ 2)

  • ตอนนี้ UI ทั้งหมดเป็น ES5 ใน String.raw ยาว 542 บรรทัด (page-assets.ts) ไม่ผ่าน typecheck ไม่มี syntax highlight และห้ามใช้ backtick หรือ ${
  • ย้ายไปเป็นไฟล์ .js จริงที่มี // @ts-check แล้วอ่านตอนสร้างหน้า จะดูแลง่ายกว่ามาก โดยไม่เปลี่ยนพฤติกรรม

สำหรับรอบนี้ไม่ต้องรื้อ แต่ควรทำก่อนที่ UI จะโตกว่านี้

ไล่แล้วยืนยัน

  • เทสต์: npm test ผ่าน 812 เทสต์ และ typecheck ไม่มี error (รันเองหลัง commit c5f35e4)
  • คืน focus หลังวาดหน้าใหม่:
    • render() (page-assets.ts:193-231) จำ activeElement.id แล้ว focus กลับหลังสร้างหน้าใหม่ control ทุกตัวมี id คงที่แล้ว เช่น sel-run:244, chip-*:332, calls-*, ev-*, call-N-toggle:371
    • ปุ่มที่กลายเป็น disabled จะส่ง focus ไปปุ่มคู่ของมัน (siblingPagerId:187)
    • คืนตำแหน่งเคอร์เซอร์ (caret) เฉพาะช่องค้นหา
  • IME: timer ของ debounce ไม่ render ระหว่างที่ IME ยังพิมพ์ไม่จบ (composition) (:428), live poll ก็ข้ามตอนนั้น (:514) และ compositionend สั่ง render เอง (:458)
  • ตัวกรองค้าง: กรณีตัวกรองทำให้รายการว่าง มีปุ่ม "ล้างตัวกรอง" ทั้งสองส่วน และยังคงจำนวนต่อหน้าเดิมไว้ (:348-359, :465-476)
  • live update: <details> ที่เปิดอยู่ยังเปิดค้างหลัง live update (state.openEvents :479-504) ส่วนการคำนวณ default run และ reset เมื่อเปลี่ยนรอบรันยังเหมือนเดิม (:520-534)
  • ความปลอดภัยและฟอนต์: ข้อความจาก log ผ่าน el() ด้วย textContent ทั้งหมด ฟอนต์ฝังจาก assets/fonts โดยไม่มี request ออกภายนอก (ยืนยันแล้วใน logs.html ของ mail-sender)

Findings

MAJORโหมด --live หยุดอัปเดตโดยไม่บอก ตราบใดที่ focus ยังอยู่บน select (page-assets.ts:515-516)

ทำไมสำคัญ
ผู้ใช้เปลี่ยนการเรียงหรือตัวกรองสถานะ แล้วนั่งดู agent ทำงาน แต่หน้าเลิกอัปเดตไปเลยจนกว่าจะคลิกที่อื่น ทั้งที่หัวหน้ายังเขียนว่า "live: อัปเดตอัตโนมัติทุก 3 วินาที" ซึ่งขัดกับเป้าหมายของโหมด live ตรง ๆ
หลักฐาน
เปลี่ยน select calls-sort → onchange → render() → focus ถูกคืนให้ select ตัวใหม่ (:220-221, ตามที่ตั้งใจทำไว้เพื่อ keyboard) → poll ทุกครั้งหลังจากนั้นเจอ activeTag === 'select' แล้ว return ไปเลย (:516) ไม่ fetch และไม่ render จนกว่า focus จะย้ายไปที่อื่น เทสต์ live ใน page-dom.test.ts:296+ ไม่ครอบกรณีนี้
แนวทางแก้ไข
เลื่อนการ render เฉพาะตอนที่ dropdown น่าจะเปิดอยู่จริง ไม่ใช่ทุกครั้งที่ select มี focus:
  • บันทึก lastSelectInteraction = Date.now() ตอน mousedown/keydown บน select แล้วข้ามเฉพาะ poll ที่เกิดภายใน 3 วินาทีหลังจากนั้น
  • หรือยังคง fetch ตามปกติแต่เลื่อนแค่ render() ออกไปไม่เกิน 1 รอบ
เพิ่มเทสต์: focus select → tick → ข้อมูลใหม่ต้องแสดงภายใน 2 tick

MAJORUI ฝั่งเบราว์เซอร์ 542 บรรทัดอยู่ใน String.raw ที่ TypeScript ตรวจไม่ได้

ทำไมสำคัญ
การแก้แต่ละครั้งพึ่งเทสต์ DOM shim อย่างเดียว:
  • พิมพ์ชื่อ property ผิด เช่น res.pgae ก็ยังผ่าน typecheck
  • editor ไม่ highlight โค้ดในสตริง
  • ต้องระวังกฎ "ห้าม backtick / ${ / </script" ทุกบรรทัด
และโค้ดโตจาก 300 เป็น 542 บรรทัดในสองรอบ
หลักฐาน
src/logview/page-assets.ts (542 บรรทัด) และ list-assets.ts เป็นสตริงทั้งไฟล์ tsconfig ไม่มี checkJs ส่วนเทสต์ตรวจ syntax ด้วย new Function ได้แค่ว่า parse ผ่าน
แนวทางแก้ไข
ทำเป็นงานถัดไป ไม่ต้องบล็อก merge:
  • ย้ายไปไว้ที่ src/logview/web/page.js และ list.js พร้อม // @ts-check และ JSDoc types
  • ให้ render.ts อ่านไฟล์ด้วย fs.readFileSync (cache ไว้) เหมือนที่ทำกับฟอนต์
  • เทสต์เดิมใช้ต่อได้ แค่เปลี่ยนแหล่งที่อ่านสตริง

NITกด "ล้างตัวกรอง" แล้ว focus หลุดไปต้นหน้า

ทำไมสำคัญ
ผู้ใช้คีย์บอร์ดกด Enter ที่ "ล้างตัวกรอง" แล้ว focus ไปอยู่ที่ <body> เพราะปุ่มหายไปหลังรายการกลับมามีข้อมูล
หลักฐาน
calls-clear/ev-clear (:352, :469) มีอยู่เฉพาะตอนรายการว่าง พอ render ใหม่ getElementById(focusId) ได้ null (:214)
แนวทางแก้ไข
ใน onclick ของปุ่มล้าง ตั้งให้ focus ไปที่ control แรกของ section นั้น (calls-status / ev-search) โดยตั้ง id เป้าหมายก่อนเรียก render()

NITaria-live อยู่บน element ที่ถูกสร้างใหม่ทุกครั้งที่ render

ทำไมสำคัญ
screen reader จะประกาศการเปลี่ยนแปลงของ live region ที่มีอยู่แล้วในหน้า แต่ .pager-info ถูกสร้างใหม่ทั้งก้อนทุกครั้ง จึงมักไม่ถูกประกาศ เช่น NVDA/Chrome ไม่อ่าน region ใหม่ที่ใส่ข้อความมาพร้อมกัน
หลักฐาน
info.setAttribute('aria-live','polite') (:175) อยู่ใน pager() ซึ่งถูกเรียกใหม่ทุกครั้งที่ render และ app.textContent = '' (:211)
แนวทางแก้ไข
ใช้ live region ตัวเดียวที่อยู่นอก #app (สร้างครั้งเดียว) แล้วเขียนข้อความ "หน้า X/Y" ลงไปหลังเปลี่ยนหน้า

NITถ้ามีหน้าเดียว ปุ่ม prev/next เป็น disabled ทั้งคู่ และ focus หาย

ทำไมสำคัญ
เปลี่ยนจำนวนต่อหน้าเป็น 50 จากปุ่ม next แล้วรายการเหลือหน้าเดียว focus จะไปอยู่บนปุ่มที่ disabled (focus ไม่ติด) แล้วหลุดไปที่ body
หลักฐาน
:215-221 ถ้าปุ่มคู่ก็ disabled ด้วย จะยังเรียก again.focus() บนปุ่มที่ disabled
แนวทางแก้ไข
ถ้าทั้งคู่ disabled ให้ย้าย focus ไปที่ select จำนวนต่อหน้า (*-size) ของ section เดียวกัน

Verdict

fix-then-ship

เหตุผลหลัก: โหมด --live หยุดอัปเดตเงียบ ๆ ทุกครั้งที่ผู้ใช้เพิ่งใช้ select เพราะ focus ถูกคืนให้ select แล้ว poll ถูกข้ามตลอด แก้ได้ในไม่กี่บรรทัด ส่วนอื่น (ตัวกรอง, pagination, ฟอนต์ที่ฝัง, typography, ความปลอดภัย) ตรวจแล้วใช้ได้ การย้าย UI ออกจาก String.raw ควรทำเป็นงานถัดไป
